# Deploy 003 — BTC Reintegration (EXP017-B)
**Fecha:** 2026-04-26  
**Rama:** master  
**Entorno:** Google Cloud Run — europe-west1

---

## Motivación

Deploy 002 simplificó el sistema a ETH-only (EXP016A) porque BTC era negativo con fees en 180 días de datos.

En esta sesión se investigó BTC con 2 años de datos (730d) usando `backtest_exp017.py`. Se encontró que **EXP017 Variante B (SL≥0.30%, RR=2:1, longs only)** es viable sobre el período completo.

Resultado de EXP017-B (con fees, 730d, 241 trades):
- Win rate : ~38%
- PF       : 1.126
- Return   : +23.6%
- Max DD   : 11.8%
- Regímenes: funciona en 3/4 (falla solo en el ATH extremo 2024-25)

---

## Cambios en este deploy

### core/paper_engine.py
- `PaperEngine` ahora acepta `state_file` como parámetro (default: `eth_state.json`)
- `_load()` y `_save()` son métodos de instancia → permite múltiples instancias independientes
- Elimina módulo-level `STATE_FILE`, `_STATE_PATH`, `_GCS_STATE` (ya no necesarios)
- `print_summary` acepta `label` opcional

### paper_monitor.py
- Restaura dual-asset con `ASSETS_CONFIG` dict
- **BTC/USDT**: `state_file=btc_state.json`, `log_prefix=btc`, `min_sl_dist_pct=0.0030`, `longs_only=True`
- **ETH/USDT**: `state_file=eth_state.json`, `log_prefix=eth`, `min_sl_dist_pct=0.0050`, `longs_only=False`
- `run_scan()` recibe `engines: dict` y `loggers: dict` (keyed by asset symbol)
- Logs separados: `logs/btc_YYYYMMDD.log` y `logs/eth_YYYYMMDD.log`

### api/main.py
- Actualizado para cargar ambos state files (`btc_state.json`, `eth_state.json`)
- `/status`: muestra equity por asset + total combinado
- `/health`: muestra `last_scans` para btc y eth separados
- `/logs/latest` y `/logs/download`: soportan `?asset=btc|eth`
- `/trades`: acepta `?asset=BTC/USDT|ETH/USDT` (ya lo soportaba)
- Banner de startup muestra config de ambos assets

### summarize_logs.py
- Nuevo flag `--asset btc|eth|all` (default: all)
- Muestra tabla + métricas + estado live por asset
- Baseline de referencia actualizado por asset

## Nota de arquitectura

Cada asset tiene su propia `PaperEngine` con su propio state file y su propio log file.  
El equity de cada asset es independiente (simulaciones separadas del mismo capital inicial).  
En el API, `/status` muestra equity por asset y un total combinado orientativo.

## Pendiente (no resuelto en este deploy)

- **Regime-agnostic edge**: ningún asset tiene un edge sólido en todos los regímenes de mercado.  
  ETH EXP016A: PF=0.944 en 730d (was 1.413 en 180d IS period).  
  BTC EXP017-B: PF=1.126 en 730d pero falla en ATH extremo.  
  → Directiva del usuario: "quiero un sistema que funcione siempre en cualquier régimen."  
  → Opciones en investigación: ADX regime filter (EXP018), mean reversion ensemble (EXP019), o rediseño desde cero.

## Comandos de deploy

